# 搭建你自己的 AI 工作空间

[English](start-here.md) | [中文](start-here.zh-CN.md) · [首页](../README.zh-CN.md)

把这份指南交给你正在使用的 AI 助手，让它一边解释基本概念，一边帮你选出合适的起步方式，把经常做的工作安置在本地文件夹里。你负责说明需求和检查结果；创建文件等技术操作，可以交给有相应工具权限的助手。

这里的 **Agent**，可以理解为有明确职责、相关资料和工作说明的 AI 助手。个人系统把这些安排、成果和未完成的任务保存在文件里，让你下次接着用。可以先从一个 Agent、一类工作开始，例如读书笔记、写作项目或学习计划。

## 1. 打开平常用的 AI 应用，选一个文件夹

使用 Codex、Claude Code，或其他已配置好本地文件操作能力的助手。新开一个对话，选定你希望保存个人系统的文件夹。新的空文件夹最容易开始；如果不知道如何选择，直接告诉助手，让它根据你的应用和操作系统带你操作。

这条路线不要求你运行终端命令。先复制下面的提示词，让助手检查自己能否读取仓库和选定目录，再决定怎么搭建。给出仓库链接，本身不会授予本地文件权限。

如果应用只有聊天功能，也可以先讨论需求、规划文件。要实际创建和重新打开本地文件，还需要相应工具能力，或由你协助手动操作。应用订阅或模型使用可能另行收费。

## 2. 复制整段提示词

仓库链接已经包含在内。开始前不需要先安装 Skill。

<!-- STARTING_PROMPT:zh-CN -->
```text
我不懂编程。请按照这个仓库的教程，带我搭建自己的本地 Agent 系统：
https://github.com/kwis7/Plug-And-Chug-Agentic-Building-Guide

先读新手指南，再了解我想让 AI 帮什么忙、正在用哪个 AI 软件、
用什么电脑。每次只问两三个问题。
推荐适合我的最简单配置，用通俗语言解释；你能实际完成的技术步骤，
请你来做。创建文件前，先让我看看准备使用的新文件夹和里面的内容，
等我确认。使用新目录，保留我已有的文件。
带我完成一个小任务、检查结果，再试试新开一个会话后能否继续。
最后给我一份简短说明：文件在哪里、下次打开什么、该怎么对你说。
如果你无法读取仓库或操作本地文件，请告诉我下一步需要做什么，
不要直接说已经搭建完成。
```

以后重新开始时，也可以直接使用这份[简短起步提示词](../skills/portable-agentic-system/pas/references/friend-starter-prompt.md#中文)。

## 3. 让助手围绕你的工作搭建

对话应该从你的需求开始。例如：“我每周读几篇文章，想写一份比较笔记，但总是找不到之前的来源，也忘了下一步要做什么。”用平常说话的方式回答就好；遇到不懂的术语，可以让它先解释。

### 第一次对话，可以是什么样子？

下面这段虚构对话用来展示顺序，不是一次实际搭建的记录：

> **你：** 我想先比较三份虚构工作坊场地资料，再试试下次不用粘贴旧聊天也能继续。
>
> **助手：** 你在用哪个 AI 应用，使用什么电脑？我会检查能否读取指南，以及能否操作你选定的本地文件夹。
>
> **助手，在你回答之后：** 我会提出一个保存来源笔记、草稿、检查后的成果和交接说明的方案。创建任何内容之前，先让你看到准确位置，等你同意。如果无法访问文件，我会说清需要你完成的下一步。

接下来，助手应该给出一个小而具体的方案：新文件夹的准确位置、这个 Agent 负责什么、资料和成果放在哪里，以及怎样在对话结束后保留进度。每一部分为什么有用，都应该说明白。你看过方案、确认后，它再创建文件。如果选定目录里已有工作，先让它查看相关文件并保留原有内容。

同意后，把技术步骤交给助手，让它展示实际创建的文件。仓库现有生成器会创建一套较完整的**标准结构（standard scaffold）**；合适时可以直接使用，也可以先安排一个更小的学习工作区。后者是单独的教学选择，不是生成器已有的“最小模式”。

确实需要下载、安装或改变访问权限时，助手应说清具体步骤，并取得相应许可。粘贴提示词启动的是一个有人参与的引导过程，不代表所有应用都能无人值守安装，也不保证接入一次就成功。

## 4. 完成一件有用的事，再核对结果

从自己的工作中挑一个低风险任务，提供少量你愿意交给工具处理的非敏感资料。例如，把三份阅读笔记整理成带来源链接的比较。让助手保存结果、重新打开文件，再对照输入核对；没有提供的信息，应明确保留为未知。

然后留下简短交接：做完了什么，用了哪些文件，还有哪些问题，下一步允许做什么。请助手填写一张使用卡，写上**你实际使用的路径**，不要只给占位符：

| 留下这张卡 | 助手应该写什么 |
|---|---|
| 下次打开哪里 | 使用的应用和准确工作目录 |
| 开始时说什么 | 指明交接文件的简短续做提示词 |
| 成果在哪里 | 已保存并核对的结果路径 |
| 进度在哪里 | 交接说明或当前任务文件的路径 |
| 下一步做什么 | 一个具体动作，以及需要的资料 |
| 检查到了哪里 | 实际观察到什么，哪些部分还没测试 |

### 填好的练习使用卡，可以是什么样子？

这张卡是根据[虚构工作坊练习](../examples/first-project/README.zh-CN.md)的[参考比较](../examples/first-project/expected/comparison.zh-CN.md)和[参考交接](../examples/first-project/expected/handoff.zh-CN.md)编写的虚构示例。下列路径相对于本地仓库副本中的 `examples/first-project/`。工作成果和交接文件需要在你的练习中创建；这张卡不能证明它们已经存在，也不是可下载的搭建结果。

- **下次打开哪里：** 有本地文件操作能力的 AI 应用，选定本地的 `examples/first-project/` 文件夹
- **开始时说什么：** “读取 `workspace/handoff.md`，只使用它允许的资料。核对成果，再起草记录中那条尚未发送的询问。”
- **成果在哪里：** `outputs/comparison.md`，草稿与三份笔记核对后保存的结果
- **进度在哪里：** `workspace/handoff.md`，记录来源、成果、信息缺口和下一步允许做的事
- **下一步做什么：** 在 `workspace/maple-question.md` 起草询问 Maple 无台阶入口的问题；不发送，也不猜测缺失信息
- **检查到了哪里：** 教学参考展示了带来源的比较和明确的未知项；你本机的文件保存与新会话续做，**实际观察之前均为未测试**

自己的使用卡应换成实际使用的应用和文件夹路径。只记录能重新打开的文件，以及实际观察过的检查。

## 5. 新开会话，试着继续

在使用卡指定的工作目录里新开一个对话，使用卡片上的续做提示词，不要粘贴旧聊天记录。例如：“读取使用卡上指定的交接文件，告诉我哪些工作已完成、哪些信息仍未知，再按记录的下一步继续，只使用其中明确列出的资料。”

检查助手是否找到实际文件、按交接说明继续；它保存了新内容时，再打开查看。成功后，在交接里记下应用、日期和观察结果。如果还没试过，就标为**续做未测试**。这次练习只验证实际观察到的行为，不代表所有接入功能或权限机制都经过了测试。

## 可选：先用虚构资料练习

[虚构工作坊案例](../examples/first-project/README.zh-CN.md)提供三份场地资料、参考答案和新会话练习。想先试试，或者还没有自己的任务时，可以用它。它是可选练习；个人系统最终应围绕你自己的经常性工作来安排。

想理解基础和具体做法，继续读[手册](handbook/index.md)。偏好自己运行命令的读者，也可以选择[快速开始](../QUICKSTART.zh-CN.md)中的手动工具包路线。助手需要更详细的引导步骤时，可以参考[完整引导协议](../skills/portable-agentic-system/pas/references/facilitation-protocol.md)（英文）；你不需要先读完或粘贴整份协议。
