# 1. 先完成一项小任务

这一章借可选的虚构练习，把做法展示出来。如果已经在[新手指南](../../start-here.zh-CN.md)中选好了自己的任务，可以把相同顺序用在那里：约定结果、使用具名资料、检查、保存，再留下交接。

假设你正在准备一场 16 人参加的工作坊，需要在 18:00 之后使用场地，而且所有人都必须能够通过无台阶入口进入。在联系任何场地之前，你希望先有一份简短比较，分清哪些选项满足条件、哪些不满足、哪些还无法判断。

[首次项目练习](../../../examples/first-project/README.zh-CN.md)提供三份合成的来源笔记。它们代表虚构场地，并非真实商家或经过实时核实的信息。这是一项资料比较练习，不包含预订、发消息或付款的授权。

## 先看什么样的结果有用

一份有用的答案不只是排名。它应当展示资料记载的事实，用同一套条件检查每个选项，说明判断如何得出，并保留未知项。

| 场地 | 容量 | 记载的开放时间 | 无台阶入口 | 判断 |
|---|---|---|---|---|
| Cedar Hall | 18 人 | 18:00–21:00 | 有 | 满足已记录的条件 |
| Willow Room | 24 人 | 09:00–17:00 | 有 | 不满足晚间使用要求 |
| Maple Studio | 20 人 | 18:00–22:00 | 未说明 | 无法确认无障碍条件 |

根据这些资料，Cedar Hall 是满足条件的候选项。这个结论有清楚的范围：它不能证明某个日期有空位，也没有确定活动时长、价格或预订条款。Maple Studio 没写入口情况，表示我们不知道，不能据此断言它没有无台阶入口。Willow Room 容量更大，也不能弥补开放时间不合适的问题。

## 使用你已有的工具

选择你已经能用的 AI 工具。如果希望它直接处理文件，它需要能读取练习资料，并且有权写入你选定的工作副本。开始前确认实际权限。如果界面只能接收粘贴文本或上传文件，就明确提供三份笔记，再自行保存它返回的 Markdown。这仍然能练习方法，只是文件加载和写回由你完成。模型或 API 的正常使用可能产生相应费用；练习本身不需要付费数据服务。

如果想保留仓库中的参考文件，先把练习复制到自己的本地练习目录，并告诉 Agent 它可以修改哪一份。从练习目录出发，可以这样交代：

```text
请读取 task-brief.md、sources/cedar.md、sources/willow.md
和 sources/maple.md。暂不读取 expected/。
只依据这些给定资料，比较适合 16 人在 18:00 之后使用、
且必须有无台阶入口的虚构场地。
将来源链接、判断和未知项写入 workspace/comparison.md。
输入缺失时明确指出，不要猜测。
不要联网、联系或预订。覆盖已有结果前，先商定具体改动。
```

教程中的 Agent 首先创建草稿。如果使用纯聊天界面，由你完成保存，并将本地文件加载标为未测试。仓库里的 `expected/comparison.md` 和 `expected/handoff.md` 是参考答案，不能证明你自己的练习已经完成。先尝试起草，再打开它们。

## 接受结果之前，沿着来源检查

打开自己生成的 `workspace/comparison.md`，沿着链接查看 `sources/` 下的三份笔记，亲自核对容量与时间。再检查推理：三个场地容量都足够，两个有晚间开放时间，而只有 Cedar 同时有晚间时间和明确记载的无台阶入口。现在可以与 `expected/comparison.md` 对照。

如果答案说 Maple 也符合要求，就追问哪份资料证实了入口情况。正确的修正是把这一项标为未知，修改判断，并留下纠正记录。再流畅的文字也不能补出资料里不存在的字段。

复核并完成必要修正后，请 Agent 把检查过的版本保存到 `outputs/comparison.md`，保留原草稿。再让它创建 `workspace/handoff.md`，记录实际检查、剩余未知、允许读写的路径，以及下一步：起草一条询问 Maple 入口情况但不发送的问题。真正观察新会话接手之前，把恢复测试记为未测试。真实预订仍然需要新信息与单独授权。
