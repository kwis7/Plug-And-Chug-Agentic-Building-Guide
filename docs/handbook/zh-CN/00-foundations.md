# 开始之前：Agent 到底怎样工作

你请 AI 比较三份资料。它读取文件、写出表格、检查一个缺失的信息，又留下笔记供下次使用。到底是什么在完成工作：模型、Agent、提示词，还是 Skill？

它们承担的作用不同。分清这些作用，你就更容易搭建一个真正有用的系统，也不会把文件夹误认为能力，或把一段好提示词当成可靠性的保证。本书所说的 **Agent**，是通过模型、指令、工作状态、可用工具和执行循环来承担某种职责的系统。具体实现可以不同：Agent 能在单次会话中运行，不一定需要本地文件，也不必有其他 Agent 配合。

## 把图看作一家正在工作的公司

下面这张图展示了本仓库的完整设计。它帮助你看清各部分职责，不要求你在开始之前就建好每一个方框。

![当前模型位于用户配置的完整 Harness 中。](../../assets/harness-concept-map.zh-CN.png)

最上方，**你是所有者**：决定目标，掌握自己的材料，并授权具有重要后果的动作。中间，**模型是当前工作的员工**：理解收到的材料，对请求进行推理，再提出回答或工具调用。模型不是整家公司，也不是公司的档案和权限系统。

**Agent 是一种工作职责**，例如负责比较来源的研究助手。指令说明任务与边界，状态记录进展，工具提供可执行的操作。同一个模型可以在不同会话中承担多个角色，使用不同的上下文和权限；同一种职责也可以先后由不同模型承担。给它取名“研究 Agent”，并不会创建一个单独训练的新模型。

周围的 **Harness** 是支持执行的整套配置：规则、文件、方法、工具、状态和检查。在图中，这些安排与当前模型处在同一个系统边界里。更换模型时，已有工作可以保留；如果同时更换运行环境，适配方式和验证也可能需要调整。

公司的比喻用来区分责任：Skill 像操作手册，工具像设备，记忆像简短交接，知识像参考资料库。只有多个角色需要路由和整合时，协调模型才承担经理职责。它仍然只是一个有明确边界的模型角色，不是必需的额外层级，也不是更高的授权来源。

这个比喻不代表意识、忠诚、永久记忆或自动访问能力。图中的质量控制，只有在对应软件已经实现并验证时才实际生效。写下规则，与机械地阻止某个动作，是两回事。

## 先分清几个基本概念

| 概念 | 在系统中承担什么作用 |
|---|---|
| 模型（model） | 理解收到的上下文，生成回答或提出动作 |
| Agent | 通过指令、状态、工具和执行循环承担一项职责 |
| 提示词（prompt） | 向模型传达请求、指令或其他材料 |
| 技能（Skill） | 打包可复用的流程与配套资源 |
| 工具（tool） | 完成读文件、执行计算等具体操作 |
| 运行环境（runtime） | 承载执行、提供上下文、调用工具并处理返回结果 |
| Harness | 配置模型执行所需的工作环境 |
| 文件（file） | 保存能够跨会话留存的信息 |
| 上下文（context） | 模型在生成当前回复时实际获得的材料 |

这些是设计中的分工，不一定分别对应不同产品。一个应用可以同时提供执行环境、工具、存储和界面。

固定工作流按预先设定的顺序运行；在 Agent 的执行循环里，模型可以根据观察结果，在系统限制内决定后续步骤。实际系统可以结合两者。这一区分参考了 [Anthropic 对工作流与 Agent 的解释](https://www.anthropic.com/engineering/building-effective-agents)，不代表对某个具体产品实现的认证。

## 提示词交代任务，Skill 提供方法

一次任务的提示词可以是：“根据给定笔记，比较适合 16 人在 18:00 之后使用、且必须有无台阶入口的场地。”它说明现在要做什么。长期规则则表达在一类工作中应持续遵循的要求，例如保留来源原文，或者让没有依据的信息保持未知。两者在被加载后都能影响模型，但适用范围和保存期限不同。

模型收到的输入不局限于你最新发出的聊天消息。运行环境也可以把相关指令、已加载的 Skill 内容和工具返回的观察结果，组装进当前上下文。

在本仓库采用的形式中，**Skill 的核心就是一份保存在 `SKILL.md` 里的可复用指令文档**。加载以后，其中的文字成为模型当前上下文的一部分。你可以把它理解为：把一份好用的提示词或方法“置顶”（pin）在固定、容易发现的位置，以便以后可靠地找到并重复使用。

这里的“置顶”说的是容易找回，不是永久激活。[Agent Skills 规范](https://agentskills.io/specification)采用先通过名称和描述发现技能、需要时再加载完整说明的方式。这不表示每轮都把全文塞进上下文，也不会自动变成更高优先级的系统消息。实际发现和加载仍取决于宿主支持。

文档可以教模型逐项检查要求、引用来源，也可以附带示例、参考资料或脚本。这些材料提供方法，不是在训练新的神经能力或修改模型权重，更不会授予工具权限。附带脚本仍需要实际执行工具按访问规则调用；写到邮件，不代表已经连接账户或获准发送。

因此，同一个模型同时收到任务、来源笔记和比较流程时，会比只收到“帮我选一个场地”有更清楚的判断依据。更好的上下文可以引导行为，但结果仍然需要检查。

## 沿着一次执行过程看清分工

首次练习使用合成笔记，并非真实场地信息。请求是比较，不是预订。一次典型的工具使用过程如下：

1. **接收任务。** 运行环境提供请求和相关指令。模型识别要求，判断需要哪些来源文件。
2. **判断下一步。** 如果还看不到笔记，模型应提出读取文件，而不是把文件名当成证据。
3. **请求工具。** 调用请求说明操作名称与参数。回复一句“我读过文件了”，并不等于真的执行了读取。
4. **由运行环境执行。** 宿主依据实际访问策略调用获准操作，可能返回文件内容，也可能拒绝访问或报告错误。
5. **使用返回结果。** 工具返回的材料进入后续工作上下文。模型比较笔记，必要时继续请求获准的证据。
6. **复核并保存。** 草稿写入 `workspace/comparison.md`。依据来源复核、纠正之后，检查过的版本进入 `outputs/comparison.md`，实际进展记录在 `workspace/handoff.md`。
7. **结束或交接。** 说明已经完成的结果与剩余限制。信息或授权不足时，下一步可能是暂停，而不是继续操作。

Cedar Hall 的给定笔记支持已记录的要求；Willow Room 的开放时间不合适；Maple Studio 没有说明无台阶入口。这个过程应当保留未知项，因为推理不能补出来源中不存在的入口说明。起草一条尚未发送的问题，可以是下一项任务，但写出问题不等于获得答案。

每一步都可能出错：路径写错、工具不可用、权限被拒绝、返回内容不完整，或模型理解有误。文件写入成功，也不能证明内容正确。没有文件工具时，聊天界面可以返回文字，由你保存，但不能声称自动写回已经发生。第 1 章会把这个过程变成一次具体练习。

## Markdown 文件到底做了什么

`.md` 是 **Markdown** 常用的文件扩展名。Markdown 是一种可编辑的纯文本格式：标题可以以 `#` 开头，列表可以用短横线，链接可以指向其他文件。不借助特殊软件，也能直接阅读其中的文字。它适合保存指令、笔记和交接，因为内容容易检查、修改和带走。

某些文件名只有在宿主约定下才有特殊意义。当运行环境能够在预期位置发现并加载它们时，`AGENTS.md` 或 `SKILL.md` 才能作为指令或技能入口。它们不是到处都能执行的文件。`RULES.md`、`workspace/handoff.md` 等名称则表达项目内的约定；工作流程需要安排读取相关内容。

下面几段小示例展示不同文件的职责。它们不是首次练习必须额外创建的文件，也不是一项可直接安装的完整 Skill：

```text
task-brief.md
比较适合 16 人在 18:00 之后使用的给定场地。
必须有无台阶入口。

RULES.md（示意的项目规则）
来源缺失的事实保持未知，不要编造。

skills/source-comparison/SKILL.md（示意流程）
依据每份来源逐项检查要求，并注明证据。

workspace/handoff.md（仅在实际发生后记录的示例状态）
草稿已保存到 workspace/comparison.md；尚待来源复核。
```

这里有三种不同的东西：**已保存的文件、当前上下文和模型权重**。文件保存文字；上下文包含为本轮工作选入的指令、对话和工具结果；权重则是模型通过训练获得的参数。保存或读取这些文件，本身不会更新模型参数。新会话靠检索相关记录恢复工作，并不是因为每条保存的事实都已经进入模型内部。

## 通过明确反馈，让系统适合自己

个人系统应当服务于你真正反复进行的工作。你可以明确指定语言、详细程度、证据标准、复核时点和交付形式。这些选择在范围清楚、能够修订时，才会持续有用。

假设你纠正一份比较：“以后的来源比较，先给简短建议，再解释依据与未知项。”这项明确偏好可以成为比较工作的规则，不必自动适用于诗歌、调试日志或所有未来对话。记录你提出的要求，不要推断你具有某种人格。

其他经验应放在不同位置。“Maple 的入口仍然未知”属于当前任务状态；反复使用的提取、比较、引用和复核步骤，可以成为 Skill；为什么来源未说明不等于否定答案，可以写成知识笔记。这样就不会让一个巨大的记忆文件混装偏好、未完成任务、流程和参考资料。

个性化改变的是模型可获得的信息与工作方法，不是自动训练。反复使用，也不能证明一个猜测的偏好正确。不要从普通纠正中推断敏感特征；只保留适当且获准的材料，并复查旧偏好是否仍然适用。

## 已经有 AI 软件，为什么还要搭建自己的系统

如果你已经使用 Codex、Claude Code 或 WorkBuddy，这里要做的是在所选软件中组织好自己的工作。本手册不假定这些产品缺少记忆、Skill 或工作空间功能。优先复用所选产品已有的运行环境、工具、指令加载与存储能力，无需另写一套调度引擎或定制应用。

个人系统是你有意组合起来的工作安排：稳定职责、自己的获准来源、有明确范围的偏好、反复有效的方法，以及带证据的当前状态。软件提供能力，你决定它们如何服务于自己的工作。有些人直接使用产品的内置安排，就已经足够。

这里的**本地**，是指把长期工作空间保留在自己能够掌握的位置。文件可以查看、备份，并在适当情况下进行版本管理，追踪哪些内容发生了变化。来源与结论保持联系，新会话可以找到下一步，其他兼容工具也可以复用获准材料。

文件保存在本地，不代表模型也在本地运行，更不表示整个流程离线。使用托管模型或连接器时，内容仍可能被发送出去。隐私取决于实际数据流、访问权限、服务设置和你提供的材料，不能由 `.md` 扩展名或文件夹名称保证。迁移时也要检查新工具如何加载指令、保存结果；工具之间并非通用即插即用。

当工作重复出现、跨越会话，或需要可追溯的结果时，这种安排会有价值。一次性的解释，普通聊天也许已经足够。长期系统也有维护成本：指令会过期，副本会分歧，方法需要复查。先完成一件有用的小事，只保留能让下次更容易的部分。[首次任务章节](01-first-task.md)会带你迈出这一步。
