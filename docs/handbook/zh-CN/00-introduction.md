# 搭建一个下次还能接着用的 AI 工作空间

和 AI 做过的好工作，应该能在下次接着用。你可能完成了一份有用的比较，找到了一种更好的资料核查方法，也可能在项目中途做出了重要决定。对话结束以后，这些成果仍应当清楚、可查，并由你掌握。

这本手册帮助你给反复进行的工作一个稳定的位置。我们先完成一件小事，保留结果背后的证据，再留下足够的状态，让另一个会话能够继续。等工作确实需要时，再加入可复用流程、更多 Agent 和更强的检查。

## 模型可以更换，工作可以保留

这里的核心想法很简单：当前使用的模型可以变化，已经积累的工作仍然属于你。资料、决定、方法、任务记录和检查过的结果，都应当以你能查看、能带走的形式保存。更换界面或模型服务，可能需要调整接入方式，但不必因此从头积累。

我们把围绕模型执行而配置的整套安排称为 **Harness**，这里译为“工作系统”。它包括模型接收的指令、能够访问的文件和工具、需要保存的状态，以及约束和检查动作的机制。其中一部分是普通文字，另一部分是能够授予权限或拒绝操作的软件。它们的作用不同，后面会逐步说明。

可以借用一次公司的比喻：模型像当前处理工作的员工，Harness 保存工作安排、记录、工具和流程，你是所有者。这个比喻有明确限度。模型没有持续的忠诚，也不会自动知道目录里的所有文件；文件夹名称不能保护隐私，写在文档中的规则不会自行执行。只有一个 Agent 时，也无需先搭建一套管理层级。

## 从看得见的结果开始

第一项练习使用三份给定笔记，比较三个虚构场地。它不需要账户、预订或联网搜索。你会得到一份带来源的比较，以及一份供下一次会话使用的交接记录。这里练习的习惯，同样适用于研究、写作、学习和软件项目。

第 1–4 章围绕这项练习展开。第 5–8 章解释什么时候需要划分职责、更换工具、加强验证，以及维护已有积累。最后的参考章把这些想法连接到仓库现有的工具。只完成第一项练习，你也已经能带走一个可用的方法。

这个小工作空间有意保持简单，并不是完整的 Portable Agentic System 项目骨架（scaffold）。生成器提供的是更完整的标准结构，包含任务清单和自动检查。等这些功能能解决你的实际问题时，再选择它。

## 让结论与证据对应

练习中的资料都是合成数据。手册里的命令与兼容性记录，描述的是仓库包含的实现，不能证明某个产品已在你的电脑上通过测试。文字指令、静态检查、新会话中的实际行为，以及外部交付，都需要各自的证据。

如果这些术语还不熟悉，先读[Agent 到底怎样工作](00-foundations.md)：用公司图讲清提示词、Skill、文件、本地系统与个性化，再试着[完成一项小任务](01-first-task.md)。阅读时始终保留一个问题：什么会让下一次接着做更容易？
