# 第一个项目：把资料整理成比较结果

[English](README.md) | [中文](README.zh-CN.md) · [从这里开始](../../docs/start-here.zh-CN.md)

为一场工作坊比较三个虚构场地。结果要简短地说明：各场地符合哪些已记录的需求，哪些资料说明它不适合，哪些信息仍然未知。然后实际检查，新会话能不能根据留下的记录继续。

所有场地资料都是**学习用的虚构数据**，不是真实场地信息，也不是最新公开研究。练习不需要搜索、发送消息或预订。这个目录是一份学习工作表，不是生成器产生的标准结构；不要对它运行标准结构验证器。

## 1. 看清每个文件的用途

| 文件或目录 | 用途 |
|---|---|
| [task-brief.md](task-brief.md) | 任务、允许的资料、产物和核对标准 |
| [sources/cedar.md](sources/cedar.md)、[willow.md](sources/willow.md)、[maple.md](sources/maple.md) | 三份现成资料，保留原文 |
| `workspace/comparison.md` | 练习时创建的草稿 |
| `outputs/comparison.md` | 核对后保存的结果 |
| `workspace/handoff.md` | 练习时创建的当前状态和下一步 |
| `expected/` | 做完后对照的参考答案，不是你的工作文件 |

[参考结果](expected/comparison.zh-CN.md)和[参考交接](expected/handoff.zh-CN.md)展示了一个完成后的节点。它们是编写的示例，不能证明你的 AI 工具已经保存文件或通过续做检查。想先自己尝试，就到第 3 步再打开 `expected/`。

## 2. 先做草稿

使用能够读取所选本地资料、并在此保存结果的工具。如果只有聊天功能，可以粘贴任务说明和三份资料，再手动保存回答；本地文件读取仍应标为**未测试**。

告诉助手这个目录的准确本地路径，然后粘贴：

```text
读取 task-brief.md，以及 sources/cedar.md、sources/willow.md、sources/maple.md。
先不要读取 expected/。场地事实只以这三份资料为依据。
在 workspace/comparison.md 写一份简短的中文比较：包含建议、每个场地一行、
资料链接和明确的未知项。不要上网或预订。如果资料缺失，指出缺少的文件，
并把结论限制在现有证据支持的范围内。不要未经商量就覆盖已有练习结果。
```

打开生成的文件，确认文件确实存在，链接也指向这些资料。助手说“已保存”，不等于你已经看到了保存的文件。

## 3. 核对并保存结果

自己读一遍三份资料，逐行核对人数、开放时间和无台阶入口。人数和时间符合要求，不能补上入口信息的缺口。“没有说明”不等于“没有”，也不等于“有”。

现在对照 [expected/comparison.zh-CN.md](expected/comparison.zh-CN.md)。措辞可以不同，但判断和证据应一致。先修正没有依据的说法，再把核对后的版本保存到 `outputs/comparison.md`。草稿继续放在 `workspace/`。

请助手创建 `workspace/handoff.md`，记录：

- 已完成什么，以及核对后的结果在哪里；
- 实际读过哪些文件，做过哪些检查；
- 尚未解决的问题，以及下一步允许做什么；
- 下一步允许读取和写入的准确文件；
- 哪些动作仍不在范围内，以及是否测试过新会话续做。

可以参考 [expected/handoff.zh-CN.md](expected/handoff.zh-CN.md)，但要记录你这次实际观察到的行为。不能把参考答案里的检查声明直接当成自己已经完成的验证。

## 4. 换一个新会话继续

结束当前对话，打开能访问同一目录的新会话，不要粘贴之前的聊天记录。使用：

```text
继续这个目录里的工作坊练习。先读 workspace/handoff.md，再只读取它允许
使用的具名资料。告诉我哪些工作已完成、哪些信息仍未知、你实际读了哪些文件。
按交接说明执行下一步：在 workspace/maple-question.md 起草一条待确认问题，
只保存，不发送。不联系任何人，不上网，不预订，不编造新的场地事实。
把实际做过的事情和仍然需要补充的信息写回交接说明。
```

确认它找到核对后的比较结果、认出未解决的入口问题，并保存一条尚未发送的询问。重新打开 `workspace/maple-question.md` 和更新后的交接说明。只有观察到这些行为，才能把续做标为已测试，并记录工具、日期和结果。没有新证据，未知项仍然未知。

新会话找不到交接时，先提供准确的本地目录路径并检查读取权限。如果交接或结果根本没保存，回到第 3 步；不要让新会话凭记忆重建。

## 5. 试一次资料缺失

再开一个新会话。保留所有原始资料，用限制允许输入的方式制造缺口，无须删除文件。粘贴：

```text
这次做资料缺失练习，只读取 task-brief.md、sources/cedar.md 和
sources/willow.md。把 sources/maple.md 视为无法取得。不要读取其他练习文件，
也不要使用以前记住的场地信息。在 workspace/missing-source-check.md 保存
证据受限的比较，指出缺少哪份资料、具体哪些结论无法支持。不要猜测资料内容。
```

通过标准：回答指出 `sources/maple.md` 无法取得，把 Maple 留为无法评估；不能从允许范围之外补出它的容量或开放时间。原先核对过的比较结果应保持不变。这检查的是明确声明的输入边界；更强的隔离还需要工具本身的权限机制。

## 这次学会了什么

资料说明依据，核对后的比较记录结论，交接说明让未完成的工作能够继续。这个练习没有测试标准生成器、运行环境 Hook 或真实场地的可预订情况。

接着读[手册](../../docs/handbook/index.md)，或者用[简短起步提示词](../../skills/portable-agentic-system/pas/references/friend-starter-prompt.md#中文)，把这种做法用到自己的一项经常性工作中。
